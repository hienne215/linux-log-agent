# SCRUM-39 offline gate support

Stacked on PR #12 at `440c2004a7742f75550765b9db339734740d80f3`, including #11,
#9/#8/#7 and Async Adapter #10. No production source is modified; no dependency
on #15–#18. This adds four focused assertions and captures actual safe observations
from the existing pipeline, not another model implementation or reasoning loop.

## Run from this checkout

Use the prepared Python 3.12.16 environment with pinned MCP SDK 2.3.0 and dependencies
from pyproject.toml. No packages, models or services are installed/changed by tests.

```bash
PYTHONDONTWRITEBYTECODE=1 python -B tests/week2_gate/run_tests.py
PYTHONDONTWRITEBYTECODE=1 python -B tests/integration_demo/run_tests.py
```

First command writes unittest results to stderr and observation JSON to stdout only
on PASS. It uses absolute paths derived from its own checkout, not another worktree;
workers get this checkout's PYTHONPATH. It never overwrites the committed artifact
implicitly. Choose a new output filename when redirecting a new observation run.

The second runs each existing suite once: llm, mcp_client, integration_boundary,
agent_acceptance, agent_loop, cli, async_llm, integration_demo. Synthetic stdio tests
require subprocess pipes; they are not live Linux diagnostics. Preflight/live-driver
unit tests mock their dependencies; no live Ollama invocation is part of the runner.

## What is actually tested

- active: one synthetic read / two mock model turns; exact application trace.
- port-conflict: two synthetic reads / three mock turns; repeated COLLECTING/ANALYZING
  transitions and evidence/citation continuity.
- permission-denied: terminal limited status/uncertainty, not a fabricated cause.
- port-conflict with tool cap 1: no second dispatch, terminal budget_exhausted and
  the first safe evidence retained (not replaced by a fake conclusion).

Every probe uses explicit Backend.MOCK -> existing AsyncDecisionSource worker
with MockHTTP.post -> Coordinator -> ToolBridge -> official SDK stdio -> existing
synthetic MCP server -> received evidence -> renderer. MockHTTP is a fake injected
HTTP transport (no TCP/HTTP socket). Its choices/conclusions are **scripted fixtures**,
not live model reasoning or empirical diagnostic accuracy. The official SDK/server
subprocess and adapter workers really execute; their owners/exit codes are checked.

No test changes a contract, registry, allowlist or production tool permissions.
The tool-cap test only tightens an existing Coordinator budget. No restart/helper,
privilege escalation, Linux collectors or inference. Existing regressions cover
faults/cleanup and CLI report persistence; see the gate report for exact references.

## Evidence

OBSERVATIONS.json is generated by an actual run, not a hand-authored snapshot of
expected outcomes. It records source revision at collection, probe/runner SHA-256,
Python/SDK versions, state traces, request/dispatch counts, evidence ID/source,
citations, owner checks, worker/server exit codes and rendered report hashes.

It was captured before committing these test files: source_revision is the unchanged
production base #12; probe/runner hashes identify the uncommitted test sources used.
No raw prompts, model reasoning, host metadata, personal paths or real logs are saved.
Four observation records are support probes, **not** four Linux evaluation runs.
All model workers and observed MCP subprocess handles were reaped at assertion time;
this does not prove anything about an Ollama backend (none was contacted).

Do not add 352/356 PASS to older overlapping suite totals or use any unittest count
as accuracy. Historical live active smoke is separate evidence, not a new run here.
