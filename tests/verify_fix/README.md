## Usage boundary

`VerifyFixBinding(client, input_schema, data_schema, result_schema, redact=...,
baseline_evidence=(), action_ids=frozenset())` is a client facade below the existing
ToolBridge. All constructor inputs are trusted application configuration, not model
input. Schemas use Draft 2020-12/format validation with external retrieval disabled.

- Expose only `binding.trusted_tool`: verify_fix, nginx.service, canonical business
  arguments. App creates schema/session/trace/logical/attempt metadata; the model
  cannot inject it. Only known application action IDs and baseline evidence refs
  may be submitted. No restart, shell, approval, polling, retry or fallback.
- Optional `until`, `action_id`, `baseline_evidence_refs` preserve absent versus
  explicit null in the request. Only an absent/null baseline normalizes to an empty
  reference list in the response, as specified by the pinned mock. Output action_id
  is nullable; output baseline references are an array, not nullable.
- Validate full canonical input/result/data; consistent native structuredContent,
  text JSON and isError mapping; correlation; check set, aggregation
  (fail > unknown > pass), baseline/action echo, fresh evidence refs and UTC window. Future observations
  beyond response completion fail closed even when until is null.
  Baseline IDs cannot stand in for new check evidence. Duplicate JSON keys fail.
- Ledger keeps received IDs/source/observed_at/unit/redacted/truncated and trusted
  baseline records. Only excerpts/check summaries/error messages can be locally
  redacted; provenance mutation fails closed. `local_redaction_applied` is internal,
  not a new wire field or a rewrite of the server redacted flag.
- `result` and `evidence` return detached bounded safe snapshots. Coordinator
  projection includes fresh evidence only; full baseline provenance remains in
  the ledger for future report integration. No evidence/citations/checks are
  generated by this binding. Findings/observations remain untrusted data.
- `checks_passed` requires ok, all requested checks pass with current evidence,
  and no truncation. Partial, fail, unknown, errors or missing references never
  pass. This is a local assessment of received checks, **not proof a fix happened**.
  Coordinator still marks semantic conclusion verification false.

Pinned Thủy mock returns **partial/unknown and no evidence**, because it cannot
verify Linux or a health profile. The actual SDK test asserts precisely this;
positive pass/fail data exist only in clearly labelled test response fixtures.

## Ownership and caller obligations

Use existing StdioMCPClient with `allowed_tools=frozenset({'verify_fix'})`. The
caller must connect/discover and compare canonical input/output discovery schemas,
then create ToolBridge with `(binding.trusted_tool,)`, a reviewed redactor and bounded
BridgeBudget. Coordinator must use the same read-only allowlist/unit scope.
`interpret=binding.interpret` projects only a previously validated safe response.
No new reasoning loop or public API change to existing components is required.

Caller retains Client/Bridge/Coordinator owners and joins cleanup on normal return,
error and cancellation. Forwarded disconnect reuses the same-task SDK/AnyIO
lifecycle; no background owner is introduced. Preserve pending owners and call
finish_cleanup again if cleanup remains pending; do not close the event loop and
claim completion. Existing Bridge/Client own timeouts, cancellation and cleanup.

Timeout/EOF after dispatch retains local correlation and execution_state unknown;
no synthetic CommonResponse or automatic reconnect is fabricated. A received but
invalid response sets response_received and fails validation. Tool-level
EXECUTION_UNKNOWN is retained as last_error and never interpreted as verified.
The Client does not expose proof of exit 2; do not infer it from generic EOF.

Caps (64 KiB serialized content + native envelope and ledger) apply after SDK
parsing, not a preparse DoS guarantee. Citation existence is not semantic proof.
Pattern redaction is not real-data privacy acceptance. No hard wall SLA.

## Reproduce

Use Python 3.12 with tests/mcp_client/requirements.txt (MCP 2.3.0) and

no dependency/model installation. Activate that venv first:

```bash
PYTHONDONTWRITEBYTECODE=1 python -B tests/verify_fix/run_tests.py
# Requires the pinned PR #6 Git object already present; no automatic fetch:
PYTHONDONTWRITEBYTECODE=1 python -B tests/verify_fix/run_tests.py --with-sdk
RUN_MCP_STDIO_SMOKE=1 PYTHONDONTWRITEBYTECODE=1 python -B tests/integration_boundary/run_composed_tests.py --baseline-ref 990f41f68c8ef13218bf825bd57ff233a8c82f1c

```

SDK runner extracts pinned mock source/schemas to a temporary directory, compares
all three schema snapshots, then calls only verify_fix through official stdio.
A fresh clone requires an explicit fetch of the pinned PR object if absent.
Composed regression loads the already merged synchronous Adapter in a temporary
tree; it is not an extra branch dependency or code copied into this branch.
