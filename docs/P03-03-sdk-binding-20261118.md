## Entrypoint and trusted configuration

`run_failed_logins_server.py` defaults to ordinary unavailable scaffold backends,
without opening auth logs or a key. Explicit opt-in requires all configuration:

```text
python run_failed_logins_server.py --linux-failed-logins --session-id evaluation-session --pseudonym-scope evaluation-scope --auth-year 2026 --auth-offset-minutes 420
```

Use the actual reviewed year/local log timezone, not the example blindly. No key,
path, executable or UID parameter is accepted from MCP or CLI. Parser failures do
not echo supplied configuration values. Live startup is Linux-only and must run
as the local mcp-log-reader UID; root/another UID or missing/invalid key fails
closed. This is not a sudo/setuid mechanism and creates no user, key or permission.
The launcher sets application session ID; matching a session ID is correlation,
not authentication. Trusted dedicated pipe/launcher ownership remains a separate
deployment requirement. Principal is the trusted local reader identity supplied
by the factory, never a field copied from MCP request JSON.

## Key epoch and permission boundary

Key location/mode and no-follow directory/FD checks remain the approved design
candidate: root-owned directory tree, fixed pseudonym.key, root:reader group,
0640, exactly 32 bytes. The operator provisions it outside runtime. Scope is
deployment configuration. Key bytes never appear in args, reports or responses.

KeyEpochPolicy checks reader UID and validates the fixed key file on each call,
comparing an internal HMAC epoch marker with the originally loaded key. This
detects revocation/rotation; it does **not** replace the owner key during a live
snapshot. Any missing/changed key or identity failure latches denial until restart;
restoring the old key cannot revive old cursors. Controlled restart is the default
rotation mechanism. This feature-authorization check is not a universal detector
of every source ACL/group change; frozen coverage refers to acquisition time.

## Owner, scheduling and native result

FailedLoginsServer has one persistent owner per dedicated connection and one
tracked background acquisition call. Shared server.py/runner.py, main entrypoint,
schemas and other tools are unchanged. Source reads still use fixed argv/paths,
bounded stdout/stderr and no shell/sudo. Each page reuses the sanitized snapshot;
input validation occurs before the access policy or source runs.

Cancellation marks the owner closing, refuses new calls, and retains acquisition
until completion. EOF/close/oversized-ID admission waits for acquisition/shared
worker cleanup, then drops cursors. No hard wall cleanup deadline/force-killed
thread guarantee is made. Native structuredContent/text/isError are consistent;
the real server native builder checks final JSON-RPC framing against 65,536 bytes.
Timing at this outer boundary includes dispatch/policy/acquisition/validation;
adapter timing is not reused as an end-to-end transport measurement.
