## Opt-in binding

```text
python run_mcp_server.py --linux-oom --oom-session-id <operator-session-id>
```

Flag is off by default. Session ID is supplied by trusted launcher configuration,
not adopted from the first MCP request; mismatches reject. `OomServer` is an
OOM-only subclass in a new task-owned file. Other tools retain the shared scaffold
dispatch. The inherited registry still exposes 12 canonical descriptors. Optional
`--fixtures` retains its existing synthetic service_status worker.

The OOM SDK endpoint no longer registers a new worker for each call. One pager
lives for one dedicated stdio connection. Acquisition runs through an owned,
tracked background task/thread using existing fixed-argv bounded journal/dmesg
helpers. This is explicitly a new **task-owned binding execution boundary**, not
a claim that #14's WorkerRunner retains Python state. Shared runner/server remain
unchanged and independent review of the new boundary is required.

Production POSIX calls require the process UID of the configured system account
`mcp-log-reader`, never root. Windows supports only diagnostic UNSUPPORTED results.
No MCP argument controls executable, path, session policy or access checker.
The UID check establishes reader execution identity, **not caller authentication**;
trusted dedicated stdio pipe/launcher ownership still needs deployment review.
Per-page access policy is rechecked; injected policy revocation clears cursors.
The default UID policy is not a general ACL/group-revocation detector. Cached
coverage is explicitly an acquisition snapshot, not a fresh source-health probe.

Cancellation marks the owner closing and retains the acquisition reference;
further work refuses. Close/EOF/oversized-ID admission waits for that acquisition
and shared worker cleanup, then destroys cursor state. No thread is abandoned or
claimed force-killed; there is no hard wall-clock cleanup SLA if the OS stalls.

## Limits, native transport and privacy

- Internal acquisition: at most 2,000 sanitized events and 1 MiB; bounded source
  reads retain existing 8-second read budget and 4 MiB per command limits. Parsing
  and confirmed cleanup add time, so the read budget is not an end-to-end SLA.
- Cache: at most 256 tokens and 8 MiB serialized snapshots. Source cut/overflow
  remains partial/OUTPUT_LIMIT with no fake continuation for discarded data.
- Wire: each page at most requested 1-200 events, with complete matching evidence.
  Exact native sizing uses the real server native builder and admitted request
  ID; final 65,536-byte check includes native duplicated JSON. Schema and ID
  admission limits are not relaxed to fit a fixture.
- Existing process-name allowlist and reconstructed messages remain the privacy
  boundary. Raw kernel text/internal identity keys are not put in snapshots.
  Operator allowlist provisioning/ownership policy still needs Linux review.
- Legacy `oom_worker.py`/VM smoke remains a bounded stateless diagnostic; its
  old non-paginated behavior is not the SDK endpoint or proof of new pagination.
