## Verified composition and its limits

The test-only flow is bytes snapshot -> parse_journal_json -> message list ->
match_literal_indices -> original entries selected by returned indices.
Explicit synthetic fixture timestamps are converted, never generated by the
harness as supposed observations. Duplicates and even out-of-time-order records
remain at their original positions. Both cores reject before returning partial
results; parser rejection prevents the matcher from running at all.

query_journal entry shape includes priority. search_log match shape does NOT:
additionalProperties=false rejects forwarding parser entries directly. A test-only
projection retains exactly timestamp/message and validates against R3, including a
negative schema test for forwarding priority. This is not a production adapter or
authorization to republish raw text. Matcher output alone is not canonical data.

Four explicit boundary timestamps (before since, at since, before until, at until)
all remain in the core output. This test documents the missing time filter rather
than claiming half-open filtering works. Unit/priority/source filters are likewise
not enforced by the composition. Envelope/output-limit semantics remain separate:
local whole-batch exceptions must not be blindly mapped to partial or error status.

No new blocking source defect was found within the published primitive scopes.
These compatibility results are NOT readiness for live MCP registration.

## Policy gates requiring Trang

The supplied parser handoff and P03-01 proposed policy identify these open gates;
this offline audit does not claim a fresh Jira/security approval:

1. Confirm reader identity/group access and application-owned unit/source allowlists.
   systemd-journal membership exposes broad journal content; unit filtering alone
   is not an authorization boundary. File-source allowlists/path binding also need
   approval before search_log gains a reader.
2. Approve message/evidence redaction rules and adversarial fixtures, including
   secrets/control text and metadata; raw parser output must never reach MCP/LLM.
3. Confirm how empty output differs from denied/unavailable/partially readable
   sources, and how incomplete history/rotation maps to coverage/status/errors.
4. Review real-source cursor ownership, query/session binding, expiry and rotation
   behavior before production continuation. R3 specifies boundaries, but the mock's
   in-memory synthetic offsets are not a real-source implementation.

Final contract/scaffold review gates remain with their independent reviewers;
this audit creates no signoff. Internal case-sensitive matching does not decide
the final endpoint query-language policy. Read-only production integration still
needs source-specific bounds, request/window filtering, evidence, safe envelopes,
correlation, SDK dispatch, cancellation cleanup and independent Linux acceptance.
