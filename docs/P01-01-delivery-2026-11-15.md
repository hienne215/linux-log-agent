## Failure/fix evidence

1. An early cap regression found that post-validation OUTPUT_LIMIT could preserve caller metadata. Scaffold error finalization now suppresses correlation metadata for that branch too; successful/partial results retain validated IDs.
2. A correlation fault fixture initially reused the submitted sentinel as its supposedly forged ID. The test fixture was corrected to produce a genuinely different ID; no production validation was relaxed.
3. The first 162-case finite-output corpus passed, but an additional infinite-stdout probe exposed Python pipe-transport destructor warnings after the process had exited. Process returncode alone was insufficient cleanup evidence. Cleanup now serializes ownership, cancels owned readers, drains/discards pipe bytes without retaining secrets, waits for EOF/writer closure, and only then drops the owner. Two regressions cover the infinite-output/EOF case. Final corpus: 164 PASS, including confirmed child exit and stdout/stderr EOF, with no event-loop-closed warning.

Logs/JUnit and the initial/final run distinction are kept in the Codex output delivery directory, not committed as machine-specific runtime dumps. No credentials or real Linux log contents were used as test data.
